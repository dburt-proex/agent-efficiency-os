# MCP 2026-07-28 Migration Delta

Status: `PROPOSED / REVIEW`  
Applies to: AEOS OpenAI Secure MCP Tunnel v0.1  
Source issue: #3

## Decision

Keep the Secure MCP Tunnel architecture. Migrate the MCP-facing contract to the `2026-07-28` protocol before enabling additional adapters.

The tunnel remains transport only. AEOS `ALLOW / REVIEW / HALT` authorization remains independent of transport authentication and MCP metadata.

## Primary references

- Model Context Protocol 2026-07-28 release: `https://blog.modelcontextprotocol.io/posts/2026-07-28/`
- TypeScript SDK migration guide: `https://ts.sdk.modelcontextprotocol.io/v2/migration/support-2026-07-28`
- OpenAI Secure MCP Tunnel / developer mode guidance: `https://help.openai.com/en/articles/12584461-developer-mode-and-full-mcp-connectors-in-chatgpt`

These references are versioned inputs. Re-check them before implementation or release.

## Contract delta

| Area | v0.1 assumption / legacy pattern | 2026-07-28 target | AEOS action |
|---|---|---|---|
| Initialization | Stateful `initialize` / `initialized` lifecycle may be assumed by older implementations | Core protocol is stateless; modern mode does not depend on protocol sessions | Remove session-state dependency from authorization and health evidence |
| Session header | `Mcp-Session-Id` may appear in older implementations | Not a required core control input | Never use it as authority; support only explicit legacy compatibility if needed |
| Protocol version | Version may be implicit in transport/client setup | `MCP-Protocol-Version` is an explicit request input | Validate and record negotiated/received version |
| Discovery | Capabilities learned primarily during initialization | `server/discover` is available for capability discovery | Add explicit discovery contract before tool admission |
| Client metadata | Session-carried client state | Request `_meta` carries relevant identity/capability metadata | Validate schemas and bind metadata to each request receipt |
| HTTP routing | Body-driven JSON-RPC routing | `Mcp-Method` and `Mcp-Name` headers support routing | Record headers and fail closed on header/body disagreement |
| List caching | Repeated list calls commonly treated as live state | List responses may include cache metadata | Treat cached capability data as versioned evidence with bounded TTL |
| Authorization issuer | OAuth validation may focus on token validity | Issuer binding is security-critical | Validate and record authorization issuer; reject issuer mismatch |
| Client registration | Dynamic Client Registration may be assumed | DCR is deprecated compatibility; CIMD is the modern direction | Record registration mode and avoid building new dependency on DCR |
| Credential reuse | Client credential storage may be global | Credentials must not be reused across authorization servers | Partition credential references by issuer; never copy secrets into receipts |
| Extensions | Capabilities mixed into core behavior | Extensions are explicitly negotiated | Maintain extension allowlist and record negotiated set |
| Tasks | Long-running work may be treated as core/session behavior | Tasks are extension-scoped (`io.modelcontextprotocol/tasks`) | Gate task operations on negotiated support; correlate task IDs |
| Deprecated primitives | Roots, Sampling, Logging, HTTP+SSE may appear in older integrations | Deprecated for new design | Do not introduce new dependencies on deprecated primitives |

## Modern request evidence contract

For every modern MCP request reaching the AEOS gateway, retain or derive the following non-secret evidence where applicable:

```yaml
mcp_protocol_version: "2026-07-28"
mcp_method: ""
mcp_name: null
mcp_request_id: ""
client_identity_ref: ""
client_capability_hash: ""
authorization_issuer_ref: ""
client_registration_mode: CIMD|DCR_LEGACY|OTHER|NONE
negotiated_extensions: []
task_id: null
correlation_id: ""
policy_version: ""
```

None of these fields authorize execution by themselves.

## Fail-closed conditions

Route to `HALT` or `REVIEW` under existing AEOS policy when:

- the protocol version is unsupported or ambiguous;
- routing headers conflict with the JSON-RPC request body;
- required client identity/correlation metadata is missing;
- authorization issuer does not match the expected issuer binding;
- credentials appear to be reused across authorization-server boundaries;
- an unapproved extension is requested;
- a task method is used without negotiated task support;
- an unknown tool is requested;
- a mutation lacks adapter-specific authorization and post-call verification.

## Compatibility mode

Legacy compatibility, if retained, must be explicit:

```yaml
compatibility_mode: legacy_pre_2026_07_28
reason: ""
allowed_until: ""
known_legacy_features: []
operator_decision_ref: ""
```

Do not silently infer legacy mode from missing modern fields.

## GE-007 mapping

Future Shared Decision Ledger receipts should map:

- `mcp_request_id` -> `correlation.mcp_request_id`
- task identifier -> `correlation.task_id`
- gateway correlation ID -> `correlation.trace_id` or source-native correlation ref
- protocol version / negotiated extensions -> `version_refs`
- policy version -> `policy_refs`
- native AEOS gate -> `decision.gate`
- post-call verification -> `verification`

AEOS remains the native authority for its gateway decision. GE-007 records/correlates the result only.

## Implementation sequence

1. Update config/policy schema to declare supported MCP protocol versions and compatibility mode.
2. Update configuration validator.
3. Add request-envelope normalization for modern headers/metadata.
4. Add issuer-binding and extension/task admission checks.
5. Add modern and legacy synthetic fixtures.
6. Add negative tests for header/body mismatch, issuer mismatch, unsupported extension, and unknown task.
7. Re-run canary ALLOW + unknown-tool HALT evidence.
8. Only after those pass, review any write-capable adapter proposal separately.

## Non-scope

- enabling mutations;
- weakening existing HALT classes;
- storing OAuth credentials in Git or receipts;
- making Secure MCP Tunnel an authorization authority;
- public MCP exposure;
- cross-project write adapters.
